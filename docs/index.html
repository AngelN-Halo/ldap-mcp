MCP · IDENTITY

LDAP / IDM MCP

Read-only LDAP identity discovery with guarded reports and schema-aware examples.

Schema mapping →Adapt the fictional extended attributes for your own directory.Tool reference →Search users, references, roles, entitlements and exports.Privacy controls →Treat identity exports as sensitive records.
At a glance
This MCP service searches identity objects and entitlements, exports bounded reports, and performs no directory writes. The included ISD attributes are intentionally fictional and require private adaptation.

Request path: Authorized MCP client → private gateway → MCP service → LDAPS / IDM directory

Quickstart

  1. Copy .env.example into ignored .env and supply an approved LDAPS endpoint and read-only bind identity.
  2. Mount a trusted CA under certs/, preserve hostname verification, and configure the actual search base.
  3. Before using extended tools, adapt the fictional isd* attribute names and filters in server.py to your privately documented schema.
  4. Validate Compose configuration locally and test with synthetic or approved identities behind an authenticated gateway.
cp .env.example .env
# Configure an approved LDAPS directory and private schema mapping
docker compose config >/dev/null
docker compose build

Do not commit a real .env, private certificates, API keys or inventory.

Deployment

This repository is an example, not a production deployment recipe. Use private configuration, approved service accounts and an access-controlled network. Inspect the resolved Compose settings on the deployment host; they may contain secrets.

Do not publish the service listener directly. Build success alone does not verify backend connectivity, caller authorization or safe output. Start with approved synthetic data and a rollback plan.

Tools & integration

Core operations include idm_health_check, idm_search_users, idm_find_identity, object lookups, references, and bounded exports. The idm_search_isd_users, idm_get_isd_user_profile, and entitlement/role operations rely on fictional ISD extended attributes.

Schema note: isdWorkforceId, isdSiteCode, and other isd* fields are literal placeholders, not standard LDAP attributes. They will not work against an ordinary directory until mapped and tested privately. Existing callers of older tool names need to migrate; there are no compatibility aliases.

Security

Compose has no published host port, not built-in caller authorization. Place an authenticated, authorized gateway in front; limit the read account, audit result scope, and set retention for exported personal records. Keep actual names, entitlements, site codes, and credentials outside Git.

Scope account privileges to the required reads and review returned data, error messages and logs before attaching AI clients.

Validation & troubleshooting

Run python -m unittest -q test_public_schema for the public schema checks, then exercise TLS, filters, export limits and caller-denial cases against approved synthetic records. Live schema adaptation is required.

If a tool fails, check private configuration, container health, TLS trust, upstream reachability, caller authorization and the relevant backend permissions before broadening access. Avoid pasting secret-bearing Compose output into issues.
